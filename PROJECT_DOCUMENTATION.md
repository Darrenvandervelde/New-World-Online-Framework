# Project Documentation (Architecture + Extension Guide)

This document is intentionally separate from `README.md` and is the full technical map of the project.

## 1) Tech Stack
- React + Vite application shell.
- Three.js scene rendering inside a React component.
- JSON-driven game content for world data, models, inventory, and object logic.

## 2) High-Level Runtime Flow
1. `src/main.jsx` mounts `<App />`.
2. `src/App.jsx` controls menu/game state, HUD, health panel, journal, inventory popup, and pause/exit popup.
3. When in game mode, `<GameCanvas />` creates the Three.js renderer, scene, camera, controls, and animation loop.
4. Scene data is loaded through `src/scenes/sceneLoader.js` from `src/data/scenes/scenes.json` and scene JSON files.

## 3) Folder/Module Connections

### Entry + UI shell
- `src/main.jsx`: bootstraps React.
- `src/App.jsx`: top-level state manager for UX flow.
- `src/styles.css`: all styling used by menu/HUD/panels/popups.

### Three.js gameplay layer
- `src/components/GameCanvas.jsx`
  - Builds and owns scene lifecycle.
  - Pulls scene layout from `loadScene()`.
  - Reads model references from `src/data/modelCatalog.json`.
  - Reads logic stats from `gameData` prop (inventory + object logic).
- `src/game/camera.js`
  - `createCamera()` and `resizeCamera()` helpers.

### Content/data layer
- `src/data/gameData.js`
  - Merges item groups and object logic into one gameData object.
- `src/data/items/*.json`
  - Consumables/tools/keys used for inventory definitions.
- `src/data/objectLogic.json`
  - Non-visual object behavior metadata.
- `src/data/worldData.json`
  - Player/journal/quest-facing data used by `App.jsx`.
- `src/data/modelCatalog.json`
  - Model id -> glTF path + fallback visual metadata.

### Scene system (new)
- `src/data/scenes/scenes.json`
  - Scene manifest (default scene + id to JSON mapping).
- `src/data/scenes/starter-valley.json`
  - Scene geometry/object placement config.
- `src/scenes/sceneLoader.js`
  - Central loader/registry for selecting scene configs.

### Inventory + debug support
- `src/game/inventory.js`
  - Inventory store and mutation API (`getItems`, `addItem`, `removeItem`).
- `src/components/InventoryPanel.jsx`
  - Renders inventory item list.
- `src/logic/devPanelLogic.js` + `src/models/devPanelModel.js`
  - Collect and normalize FPS/render metrics for the dev panel.

## 4) Scene JSON Contract
Each scene JSON should follow:

```json
{
  "scene": {
    "name": "scene-id",
    "spawn": [0, 1.6, 0],
    "renderDistance": 26
  },
  "areas": [
    {
      "id": "area-id",
      "position": [0, 0, 0],
      "size": [16, 0.5, 16],
      "color": "#1e293b"
    }
  ],
  "objects": [
    {
      "id": "object-id",
      "modelId": "crate",
      "position": [0, 0.5, 0],
      "rotation": [0, 0, 0],
      "scale": [1, 1, 1]
    }
  ]
}
```

## 5) How to Add a New Scene
1. Create a new file in `src/data/scenes/` (example: `ruins.json`).
2. Add the scene key/path to `src/data/scenes/scenes.json` under `scenes`.
3. Register the imported scene in `src/scenes/sceneLoader.js` inside `sceneRegistry`.
4. Optionally change `defaultScene` in `scenes.json`.
5. Ensure every object `modelId` exists in `src/data/modelCatalog.json`.

## 6) How to Add New Objects to a Scene
1. Add a new object entry to the target scene JSON `objects[]`.
2. Reuse existing `modelId` or add one to `modelCatalog.json`.
3. If object needs game behavior metadata, add matching object entry in `src/data/objectLogic.json`.
4. Keep consistent ids so visual object and logic object can be correlated.

## 7) How to Add New React Components
1. Create component file in `src/components/`.
2. Import and use it in `App.jsx` (UI) or `GameCanvas.jsx` (3D-bound UI).
3. Keep data flow prop-driven from `App` when possible.
4. For non-UI logic, place reusable code in `src/game/` or `src/logic/` and keep components thin.

## 8) How the Current Pieces Connect (Practical)
- `App.jsx` creates inventory via `createInventory(gameData.inventoryItems)`.
- `App.jsx` passes `gameData` into `GameCanvas`.
- `GameCanvas` uses:
  - `loadScene()` for layout/objects,
  - `modelCatalog` for model assets,
  - `gameData.objectLogic` to compute interactable object info,
  - `createDevPanelCollector` for render performance stats.
- `InventoryPanel` reads `items` generated by inventory module and shown in popup.

## 9) Common Extension Checklist
- Added/updated JSON data file.
- Added required imports/registrations.
- Updated IDs consistently across scene/model/logic layers.
- Verified scene loads without blocking overlay.
- Verified dev panel counts still make sense.

## 10) Notes
- The scene loader currently uses explicit imports/registry for bundled JSON files.
- This is deliberate for predictable builds and easy future validation hooks.
